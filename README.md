# Многокамерный трекинг людей и проекция на пол

Главный запускаемый файл проекта — track_project.py. Он объединяет YOLO, локальный Deep SORT с OSNet, граф камер, проекцию положения на пол и создание выходных видео.

Для каждого входного MP4 создаются два видео: bbox с глобальным ID и проекция с точками на белом фоне. Для пяти камер получится десять видео.

## Установка

Откройте PowerShell в корне проекта:

~~~powershell
cd C:\Users\danii\projects\test
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install --upgrade pip
.venv\Scripts\python -m pip install -r requirements.txt
~~~

Веса YOLO должны лежать в корне проекта, например yolo11m.pt. При первом запуске OSNet скачает веса. CPU поддерживается; для GPU установите совместимую CUDA-версию PyTorch и используйте --device cuda.

## Входные файлы и ID камер

Папка --videos должна содержать MP4-файлы. Они сортируются по имени. Если в имени есть camera_1 ... camera_5 или camera_new_1 ... camera_new_5, номер из имени используется как ID камеры. Для файлов без номера можно задать соответствие вручную, в порядке сортировки:

~~~powershell
.venv\Scripts\python track_project.py --videos my_videos --camera-ids 1,2,3,4,5
~~~

В одной папке не должно быть нескольких файлов с одинаковым номером камеры. Пять входных файлов дадут пять bbox-видео и пять projection-видео.

## Полный запуск

~~~powershell
$env:PYTHONDONTWRITEBYTECODE="1"
.venv\Scripts\python track_project.py `
  --videos videos `
  --output outputs_unified `
  --model yolo11m.pt `
  --device cuda `
  --devices cuda:0,cuda:1 `
  --step 5 `
  --conf 0.15 `
  --det-iou 0.50 `
  --imgsz 1280 `
  --track-iou 0.70 `
  --track-cosine 0.35 `
  --track-max-age-sec 2 `
  --n-init 3 `
  --min-segment-frames 3 `
  --reid-threshold 0.58 `
  --global-gap 60 `
  --max-graph-hops 4
~~~

В PowerShell обратный апостроф продолжения команды должен быть последним символом строки. Для короткой проверки добавьте --max-frames 120. Быстрый CPU-вариант: --step 10 --imgsz 640. Для более точного результата используйте --step 1 или --step 2, это медленнее.

## Результаты

В папке outputs_unified появятся:

~~~text
tracks_projection.json
embeddings.json
tracked\*_tracked.mp4
projections\*_projection.mp4
~~~

tracked содержит исходные кадры с bbox и глобальными ID. projections содержит белый фон, положение человека и ID. Рисуются только подтверждённые наблюдения, поэтому bbox не удерживается на кадрах, где детекции нет.

tracks_projection.json содержит параметры, калибровки, локальные сегменты, глобальные ID, наблюдения, bbox, пиксельные точки и координаты проекции. embeddings.json сохраняет L2-нормированный вектор на каждое подтверждённое наблюдение, с камерой, local_id, global_id, кадром и временем. Размер OSNet-вектора обычно 512.

При --no-reid OSNet выключен, Deep SORT использует HSV-гистограммы как baseline. embeddings.json всё равно создаётся, но feature_type будет hsv, это не OSNet-векторы.

При задании нескольких устройств камеры распределяются между отдельными
процессами. Каждый процесс загружает свою копию YOLO и OSNet, после чего общий
процесс объединяет сегменты всех камер в global_id. Для `cuda:0,cuda:1` среда
должна показывать минимум две GPU через `torch.cuda.device_count()`. Обычный
Colab с одной T4 не может использовать две GPU; в нём оставьте только
`--device cuda`.

Межкамерное объединение выполняется в два этапа. Сначала близкие по времени
фрагменты одной камеры объединяются по OSNet-признакам. Затем кандидаты между
камерами сортируются по временному разрыву, перекрытию и cosine similarity.
Для каждой пары камер один локальный сегмент не может быть сопоставлен сразу с
несколькими сегментами этой пары. Это уменьшает эффект жадного объединения,
когда дальняя похожая детекция блокирует правильное сопоставление на соседней
камере. По умолчанию NMS IoU YOLO равен 0.50; его можно переопределить через
`--det-iou`.

## Граф камер и состояния видимости

Файл camera_graph.json описывает состояния, в которых один человек может быть
виден одновременно в нескольких камерах:

~~~text
(2) -> (2,1) -> (1,3) -> (3,5) -> (3,5,4) -> (3)
                                             или (4)
~~~

Это не правило, что человек обязан исчезнуть из исходной камеры до появления в
следующей. Например, состояние (2,1) означает одновременную видимость в 2 и 1,
а (3,5,4) — одновременную видимость в 3, 5 и 4. Состояние (2,1) может быть
достигнуто из (2) или из (1,3), как задано в state_transitions. Состояние
(1,3) также может вести обратно к (2,1) или дальше к (3,5), поэтому
одновременная видимость в соседних камерах не считается ошибкой.

При объединении сегментов код проверяет интервалы всех камер, строит активное
множество камер на каждом временном участке и проверяет путь по состояниям. Два
сегмента разных камер могут перекрываться по времени. Пересечение двух
сегментов одной камеры запрещено, потому что это два локальных человека в одной
камере. Возможность выхода из помещения означает, что следующий сегмент может
отсутствовать. memory_until в JSON показывает время, до которого global_id может
продолжиться. Видео содержит только реальные детекции, пропущенные кадры не
дорисовываются.

## Проекция и калибровка

В camera_calibrations.json общие параметры стола применяются ко всем пяти камерам:
размер 2.74 x 1.525 м, высота столешницы 0.76 м и одинаковое фокусное
расстояние 1400 px. Точки 689,618; 1603,499; 1888,833; 751,1081 являются
общей разметкой плоскости стола для каждой камеры, согласно твоему условию.
Если для отдельной камеры на изображении точки отличаются, добавь её значения
в cameras в JSON — они переопределят common.

Для метрической проекции код строит луч K^-1 * pixel, переводит его в мировую систему через R^T и пересекает плоскость. При --floor-point head верх bbox считается точкой головы на высоте --person-height; затем её x и y переносятся вертикально на пол z=0. При --floor-point feet нижняя точка bbox сразу пересекается с z=0.

Средняя ошибка репроекции рассчитывается отдельно для каждой камеры. При
одинаковых входных точках и разрешении она будет одинаковой. Значение ошибки
при фокусном расстоянии 1400 px — оценка, а не гарантия метрической точности:
точная калибровка требует реальных fx, fy, cx, cy и дисторсии. Если камеры
имеют разные точки стола на изображении, задайте их отдельно. Пример:

~~~json
{
  "cameras": {
    "1": {
      "focal_length": 1400,
      "table_points": [[x1, y1], [x2, y2], [x3, y3], [x4, y4]]
    }
  }
}
~~~

Порядок точек для текущей реализации такой: первая точка соответствует
мировому углу (0, table_depth, table_height), вторая — (table_width,
table_depth, table_height), третья — (table_width, 0, table_height), четвёртая —
(0, 0, table_height). Нельзя менять этот порядок без одновременной смены
мировых точек в коде.

## Проверка результата

Короткий smoke-тест:

~~~powershell
.venv\Scripts\python track_project.py `
  --videos videos `
  --output outputs_smoke `
  --model yolo11m.pt `
  --device cpu `
  --step 10 `
  --max-frames 120 `
  --imgsz 640 `
  --conf 0.15
~~~

Затем проверьте файлы и данные:

~~~powershell
(Get-ChildItem outputs_smoke\tracked -Filter *.mp4).Count
(Get-ChildItem outputs_smoke\projections -Filter *.mp4).Count
$report = Get-Content outputs_smoke\tracks_projection.json -Raw | ConvertFrom-Json
$emb = Get-Content outputs_smoke\embeddings.json -Raw | ConvertFrom-Json
$report.total_tracks
$emb.records.Count
~~~

Для пяти входных файлов оба количества MP4 должны быть 5. Убедитесь, что reid равно osnet_x1_0, embeddings.records не пустой, feature_type равно osnet и размер векторов одинаковый. Если треков или embeddings нет, проверьте кадры с людьми, уменьшите --conf, уменьшите --step, а также проверьте --n-init и --min-segment-frames.

Синтаксис и форматирование:

~~~powershell
$env:PYTHONDONTWRITEBYTECODE="1"
.venv\Scripts\python -c "import ast; from pathlib import Path; [ast.parse(p.read_text(encoding='utf-8')) for p in map(Path, ['track_project.py','analyze.py','render.py','project_people_world.py'])]; print('AST OK')"
.venv\Scripts\python -m black --check track_project.py analyze.py render.py project_people_world.py
~~~

## Что ещё нужно доделать и проверить

- Добавить калибровки камер 1, 2, 3 и 5. Без них нельзя честно сравнивать метрические позиции по всем камерам.
- Проверить синхронизацию времени начала записей. Время сегмента считается от нулевого кадра каждого видео; при разном времени старта задайте, например, --camera-offsets 1=0,2=1.25,3=-0.4.
- Подобрать --reid-threshold, --local-reid-threshold, --track-cosine и --conf по размеченным переходам. Значения по умолчанию — стартовые.
- Просмотреть перекрытия людей, пропуски YOLO, похожую одежду и переходы 2->1, 1->3, 3->5, 5->4.
- Проверить ложные слияния и дубли global_id по ручной разметке. OSNet не гарантирует идеальную идентификацию без оценки на этих видео.
- При необходимости сравнить текущий локальный Deep SORT с Hybrid-SORT на тех же участках.
- Полная обработка пяти видео на CPU может занять много времени.

Другие скрипты проекта: analyze.py запускает отдельный аналитический конвейер, render.py рисует его JSON-отчёт, detect_render.py — утилита детекции/отрисовки, project_people_world.py — отдельная проекция одной камеры, app.py — экспериментальный интерфейс. Для объединённого многокамерного запуска используйте track_project.py.
