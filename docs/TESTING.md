# Тестирование

## Текущее состояние

В репозитории нет автоматического набора тестов и CI-конфигурации. Проверки ниже являются smoke-проверками окружения и текущей реализации, а не заменой регрессионных тестов.

Проверено:

- server.py и track_project.py проходят py_compile;
- web/app.js, web/exports.js и web/overlay.js проходят node --check;
- установленный FFmpeg поддерживает libx264;
- созданные видео определяются как H.264/avc1 с yuv420p;
- запрос диапазона байтов к видео возвращает 206 Partial Content;
- health endpoint сервера отвечает HTTP 200.

## Чего не хватает

- unit-тестов нормализации графа, идентификаторов камер, временных интервалов, IoU и проекции;
- API-тестов FastAPI с TestClient или httpx;
- интеграционного теста на коротком видео-фрагменте;
- проверки unified JSON по формальной JSON Schema или Pydantic-модели;
- автоматической проверки H.264-совместимости каждого результата;
- browser smoke-тестов интерфейса и воспроизведения видео;
- проверки конкурентного создания экспериментов и последовательной нумерации;
- CI для запуска этих проверок на чистом окружении;
- настоящего CSV с результатами: строка в шаблоне помечена как DELETE THIS EXAMPLE ROW.

Рекомендуемый набор инструментов: pytest, FastAPI TestClient/httpx, jsonschema или Pydantic, Playwright и ffprobe.

## Минимальная ручная проверка

1. Запустите сервер и убедитесь, что /api/health возвращает успешный ответ.
2. Создайте анализ на отрезке 60–90 секунд с шагом 20.
3. Проверьте появление каталога runs/N, unified JSON и tracked-видео.
4. Откройте видео в браузере, запустите и остановите все камеры общей кнопкой.
5. Обновите страницу и убедитесь, что список эксперимента и ссылки на результаты доступны.
