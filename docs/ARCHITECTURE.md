# Архитектура

## Назначение

Рабочая часть репозитория принимает видео с нескольких камер, обнаруживает людей, строит локальные треки, объединяет их между камерами и возвращает видео с bbox и unified-результаты через web-интерфейс. Каталог hacathon_template-main описывает отдельный акустический шаблон и не является реализацией текущего конвейера.

## Серверный слой

server.py поднимает FastAPI-приложение и отвечает за раздачу файлов web, API списка экспериментов, запуск анализа в фоне через ThreadPoolExecutor, передачу параметров анализа, импорт готового unified-результата, выдачу отчётов и видео, а также поддержку byte range для потоковой загрузки.

Состояние задач хранится в памяти процесса. Файлы результатов сохраняются в runs/<N>/.

## Конвейер анализа

track_project.py является основным unified-конвейером. Последовательность обработки:

1. Поиск исходных .mkv и .mp4 в data/.
2. Выбор временного отрезка и обработка каждого step-го кадра.
3. Детекция людей YOLO и построение локальных треков Deep SORT.
4. Извлечение признаков Re-ID через OSNet; при недоступности модели используется HSV-признак.
5. Нормализация идентификаторов камер и объединение локальных сегментов по графу камер, времени и сходству признаков.
6. Проекция точек на мировую плоскость с использованием калибровок и карты помещения.
7. Запись unified JSON, embeddings и H.264-видео с уже нанесёнными bbox.

Наложение bbox выполняется во время формирования tracked-видео. Повторно наносить bbox на стороне web-клиента не требуется; отдельные legacy-скрипты могут использоваться для старых сценариев.

## Web-клиент

Каталог web/ содержит index.html, app.js, styles.css, exports.js и overlay.js. Они отвечают соответственно за разметку, запросы к API и управление представлением, стили, экспорт и legacy-визуальные слои.

Видео в интерфейсе H.264/avc1, yuv420p, с faststart, что позволяет браузеру начинать воспроизведение до полной загрузки файла.

## Конфигурация и данные

Параметры помещения находятся в camera_graph.json, camera_calibrations.json и office_map.json. Веса детектора находятся в yolo11m.pt. Исходные MKV-файлы размещаются в data/, результаты — в runs/.

## Формат unified-результата

Основной файл runs/<N>/tracks_projection.json содержит глобальные треки с идентификатором человека, камерой, временными интервалами и координатами проекции. Точные поля следует считать контрактом текущей реализации и проверять по фактическому JSON: формальная схема в репозитории пока не закреплена.

## Логирование и ответы 304

Сервер пишет в консоль запуск задач, ошибки и HTTP-доступ. Строки вида GET /styles.css ... 304 Not Modified означают успешную проверку браузером кешированной версии статического файла. Это не ошибка: сервер сообщил, что файл не изменился и повторно передавать его не нужно.
